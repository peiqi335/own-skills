# 凝胶标注

输出符合第二批风格、引线对应本图孔位的独立 PNG。只做用户要求的定位或标注，不修改实验页面，不解释 PCR 结果。孔号默认是胶图上的物理孔号：每排按图上左→右从 1 开始；它与实验记录中的上样顺序是两个字段，不能互换。Marker 也按其实际物理孔建立锚点，不能因为它在记录中排在某个样本前后而移动。

## 简短请求与文件定位

用户只需提供大致位置或图名，以及本次特有的泳道说明；不要求完整文件路径、重复流程原则或逐步操作指令。默认采用轻量 Plan 核对、固定流程 Build 执行；尚无确认方案时先给孔表和方案，不直接绘制。用户明确要求仅定位或仅改指定文字时按其范围处理。单纯标签更正沿用已核验的几何和身份映射，只改指定文字并实际查看成图；不重做完整 Plan 或扫描。若原几何未核验或本次变更影响引线，再执行受影响的定位核验。

- 用户说“第二批”“今天导入的胶”“9.8凝胶1”等，先按指定范围检索实际文件。第二批默认在 `1.原始资料/实验数据/电泳 第二批/`；位置不明时先在 `1.原始资料/实验数据/` 内检索，不扫描个人日记。
- 用 `rg --files --hidden --no-ignore <目标目录>` 枚举图片，再按用户给的日期、名称或批次筛选；此目录可能被 Git 忽略，普通 `rg --files` 无结果不能据此认定文件不存在。
- 区分原图与文件名含 `（标注）` 等后缀的成图。唯一匹配原图就直接继续，并在进度中说明选中的文件；多张候选无法区分时，列出简短文件名只问选哪张。不凭修改时间把一张图当成“最新实验”，不静默拿旧标注当原图。
- 用户点名的批次或实施记录也由模型在对应知识库目录查找，提取已记录的身份信息。用户本轮说明覆盖旧记录；记录缺少上样顺序时不能从计划管数或胶图补造。
- 新任务读取当前 skill；同一任务已读且未变化时不重复读取，引用只在对应步骤需要时加载。以磁盘版本为准，不依赖旧对话里记住的规则。风格参考、扫描、真实读图、纠偏、成图验收和原图保护均由本 skill 默认承担，不让用户每次重述。

## 证据与边界

- 原图和已有标注保持不变；新结果默认写原图同目录，测试结果只写 `/tmp`。命名 `{原名}（标注）（{用户提供的本次内容}）.png`。
- 新定位或完整标注的**几何**来自这张图的本轮扫描；单纯标签更正适用上方的复用规则：胶块位置、孔排、孔壁围成的孔心、倾斜、可用标签空间、Marker 条带位置。每孔沿孔壁边界逐孔定中心，不能用均分孔距、亮度峰、向下延伸的条带或相邻孔推算，也不能抄旧图的绝对坐标。
- **身份**来自用户说明或用户指定的实验记录：样本、分组、加样/空孔、PC、NTC 和参数。图上没有条带不等于空孔，图像不能补实验身份。缺失只问影响标注的那一项；已知部分可先定位。
- 用户给出的物理孔顺序优先；实验记录中的上样顺序只作独立身份字段。各 NTC 独立核对，不能继承邻近样本梯度。未指定不读取 `3.记录/`。
- bp 数值只能来自用户给定或已核实的 ladder 规格；记录依据，再从本图读 y。不明规格可保留 Marker 而省略 bp 尺。

## Plan：轻量核对与完整方案

按大致位置找到原图，只查看确认孔排、孔数和顺序所需的图片。按需读取参考文档以选择参考图，不在此阶段运行完整扫描、测逐孔坐标、试排版或生成定位预览、正式标注。图片不足以确认孔数时明确待确认，不猜一个孔数填表。

根据用户说明逐孔展开身份；没有说明的孔标为待确认，不能从无条带认定空孔。用户只核对实验身份和标签，不需要提供像素坐标。同一回复先给孔表，再给完整执行方案，使用以下结构：

- 原图：实际路径；参考图：按胶型选定的路径；风格：用户要求及参考配色；输出：新文件路径。
- 逐孔表：`排号 | 物理孔号（每排左→右，1-based） | 上样顺序（仅在记录明确时填写） | 样本/Marker/NTC/空孔或待确认 | 参数 | 最终标签 | 身份依据`。所有可见孔逐一列出，各 NTC 独立填写。脚本的 `lane_x`/`lane_y` 和 `marker_indices` 只按物理孔号建立；上样顺序不会重排坐标。
- 待确认项：只列会影响对应关系或标签的缺失信息。
- 执行方案：完整列出下方 Build 的七个步骤、通过条件和纠错分支，不能只写“按 skill 执行”。坐标、字号和高度留在指定步骤内测定，不虚构具体值。

输出后等待用户核对。用户更正时给出完整替代孔表和方案；Build 使用最近确认的完整版本，不能拼接旧版本。用户确认并要求执行后进入 Build；仅切换模式不等于执行指令，实际操作服从宿主模式权限。已有用户确认的完整 Plan 时直接进入 Build，不再次询问同一授权。

## Build：固定执行流程

固定的是步骤、通过条件及纠错分支，不是尚未测量的参数。沿用已读取的当前 skill 和最近确认方案，按以下顺序执行，不另起方案；不重复要求用户确认已确认内容。

正常标注直接使用参考页中的命令和字段，不预读脚本源码，也不逐个运行 `--help`；只有实际报错且接口说明不能解决时才查对应代码。同一阶段的独立文件可批量读取，依赖上一阶段验收的操作仍须顺序执行。

1. **确认输入与风格。** 核对原图和确认孔表，阅读 [style.md](references/style.md) 并实际查看相近参考图，记录原图及已有参考图 SHA-256。新流程在 spec 顶层写入同一真实 `source_sha256`；旧 spec 可省略，若提供则必须匹配。使用步骤2的 grid 创建独立临时目录，后续仅复用本轮目录。参考图只提供风格，不复制定位误差。
2. **扫描与定位。** 按 [scan.md](references/scan.md) 生成并实际读取全图网格和各排孔槽分栏；在工作孔表追加每孔可见左/右孔壁 x、中点 x 和孔腔中心 y，不额外写长报告。保留空孔位置，不使用均分公式、亮度峰或向下条带。边界不清的孔记录不确定项，不能把最暗像素写成已核验孔心。明确用户1-based物理孔号到脚本0-based索引的转换；上样顺序仅作身份记录，不改物理坐标。Marker 使用其实际物理孔作锚点。
3. **定位验收（1:1 局部孔槽对照）。** 用 spec 生成 lanes，批量读取同一阶段的未覆盖原图分栏与叠线分栏，保留原始像素细节，不默认每孔单独裁图，也不把不同阶段的图混在一次验收中。逐孔、逐 x/y 对照孔壁与线终点，检查线穿过孔心、终点对应孔槽；不能以一次检查宣称 100% 正确，边界不清就记录不确定。偏心则只修正受影响孔，重新生成并复查受影响孔及整体分栏；倾斜孔排使用逐孔 y。全部通过后才能绘制。
4. **确定绘图参数。** 按确认孔表和参考风格设置文字层级、分组括号、逐孔引线、配色与留白；实际样品不能误用纯标题组的无引线设置。需要 bp 尺时核实 ladder 依据并读取本图条带位置；依据不足明确省略 bp 尺，不补造数值。`bp_target_x` 必须来自本图实际条带外侧的读图位置并做坐标边界校验。
5. **绘制候选图。** 将核验后的坐标、标签和布局写入 spec，运行 `annotate_gel.py SPEC.json --review-dir RUN/review` 渲染本轮临时 PNG并生成 review manifest。必要时加顶部黑色留白，不裁切或拉伸原图。
6. **成图验收与修正。** 按 manifest 批量实际读取候选全图、未覆盖原图与叠线孔槽对照、标签区及 bp 局部；逐孔检查身份、漏线、孔心、线长、空孔、各 NTC、bp、重叠、裁切和条带遮挡。文字碰撞或图元越界按脚本报告的具体对象修正。几何错误返回步骤3，排版错误返回步骤4；局部修正只复查受影响局部并再读整体。配置与确认标签不一致时纠正配置并重新验收。生成文件、review manifest 或退出码0都不代表孔心已被证明正确。
7. **交付。** 确认原图及已有参考图哈希未变，通过后保存新命名 RGB PNG，提供完整路径和预览，不覆盖已有标注。

缺失身份或发现孔数、身份对应与方案冲突时，暂停受影响工作并报告具体差异，不能擅自把11孔改为10孔；普通坐标和排版纠偏自行完成，不逐张要求用户批准预览。进度说明不能替代实际操作，未完成的检查不能写成已通过。

## 真实读图与故障分辨

读图必须使用宿主真实暴露的文件/图像读取工具：
- **OpenCode 环境**：使用 `read` 工具读取图像路径，它会将图片作为视觉附件载入模型上下文。
- **Codex 环境**：先生成图片，再调用当前会话真实暴露的读图工具（如 `view_image`，参数如 `{"path": "/tmp/codex/gel-annotation/<本次目录>/grid.jpg"}`）。若通过 `functions.exec` 暴露 `tools.view_image`，必须把返回图片发送到模型上下文。
- **agy 环境**：使用真实暴露的 `view_file` 读取原图、未覆盖原图分栏、叠线分栏和最终图；只有文件内容实际进入模型上下文才算读图。

不要只打印路径、读取 base64 或在回复里贴图片链接来冒充模型看图。工具名以实际环境为准。

`.codex/skills` 可能只是指向 `.agents/skills` 的符号链接，这不是错误；可统一使用 `.agents/skills`，但同一轮命令应保持路径一致。

遇到阻塞时区分：未暴露读图工具；已暴露但未发出调用；调用返回明确错误；调用成功但图片未进入模型上下文。报告真实返回和最后完成阶段，不猜孔位，也不把模型未调用解释成“不支持视觉”。本 skill 无法修复接入层；只有目标模型真正完成读图和最终复核，才能宣布该工作流通过。

## 验证

- 新定位或完整标注：本轮全图、未覆盖原图、逐排孔槽叠线对照和最终图均有真实读图记录，坐标对应本轮原图；逐孔记录 x/y 对照结果和不确定项，不能用“100%准确”概括。单纯标签更正：复用可核实的已验收几何，只检查指定文字及成图未发生意外变化；无法核实旧几何时执行受影响的定位核验。
- 孔表覆盖空孔位置；标签身份有依据；NTC 独立核对；bp 有规格依据。
- 单孔无组括号；多孔组正确；线按孔壁读图的中心落点，文字清晰，无裁切、重叠或条带遮挡。文件检查只能发现声明的越界或碰撞，不能证明孔心正确。
- 输出为新 RGB PNG；原图和已有参考图的 SHA-256 不变；仅当本任务修改了仓库文本文件时运行 `git diff --check`。
