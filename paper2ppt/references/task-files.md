# 任务文件、当前基准与版本

默认根目录 `/home/qi/文档/法医动物非人源/6.文献汇报/`，用户指定位置优先。核实后生成 `第一作者_年份_简短题名`，通过 DOI/源 SHA-256 匹配已有任务；同名不同篇加短 DOI 或源哈希，不凭简称合并。

按阶段创建，不预建空文件，不修改 Vault 入口。Vault 内页面/附件用 Wiki 链接，外部网站用 Markdown；跨 Vault 按仓库规则记录路径与专属链接。

| 文件或目录 | 创建时机及内容 |
|---|---|
| `00.任务进度.md` | 身份核实后；书目信息、源链接/哈希、材料清单、来源充分性与实际覆盖、汇报条件、当前阶段/待答点/下一步、当前 PPT 链接/哈希及制作授权 |
| `01.精读笔记.md` | 阅读时；摘要对照、引言、主线框架、正文配图、拟议主线；文末覆盖/主张/转换核查。答疑回填原位置 |
| `02.讨论与汇报主线.md` | 讨论时；原文与汇报顺序对照、有效决定、依赖和边界、用户确认内容/日期/原话；被替代方案保留为历史 |
| `03.逐页安排.md` | 主线确认后；实际标题、问题归属、完整图表、具体上屏解释、限定、备注补充、时间估算、分页确认依据 |
| `04.原图清单.md` | 准备汇报资产时；按原图规则记录来源、提取、实际资产和当前目标页；辅助归纳表单独标识 |
| `05.验收记录.md` | 制作检查时；当前文件/哈希、各质量门证据、逐页视觉检查范围、缺口、修订和未执行项 |
| `讲解图/` | 阅读讲解需要时保存忠实图像 |
| `原图/` | 制作实际使用的忠实资产，不预复制整包 |
| `汇报/` | 当前工作稿和正式交付 PPTX；不堆每次小改的副本 |

阶段为识别材料、阅读中、讨论中、待主线确认、分页中、待分页确认、制作中、待验收、已交付，可附暂停原因。来源充分性、阶段与质量状态是三件事，不能互相替代。

## 工作稿与正式交付

- 源 PDF、全文、JSON、图片只读留原处，不移动整包或自动沉淀知识。
- 初始工作稿可用 `第一作者_年份_文献汇报_工作稿.pptx`。正式首次交付使用未占用的 `_v01.pptx`；交付后修订递增正式版本。若用户已使用其他名称，保留当前路径，不为统一名称再造文件。
- 同一工作稿持续迭代，不把每个小改都变成新交付版。修改前保存一个可恢复检查点；使用当前环境允许的持久备份/版本机制，默认在任务目录隐藏的 `.checkpoints/` 中保存输入文件哈希命名的副本。相同内容不重复备份，不自动删除旧检查点。
- 用户明确要求就地改时更新当前文件，仍保护修改前基准；用户要求清理时只处理其授权的具体范围，不默认删除历史文件。
- 预览、联系表、中转 PDF、结构原始输出和临时构建文件放 `/tmp/paper2ppt/<任务标识>/<运行标识>/`。中转 PDF 不是文献转换产物，不归档进原始资料。
- 不默认交付 PDF、独立讲稿、XLSX 或重复台账。若确需脚本再生正式文件，将必要构建源与其输入资产/当前 PPT 哈希持久保存到任务 `构建/`；不保留大量试验脚本，也不能把临时脚本说成永久可用。

## 手改稿保护

修订前读取当前 PPT 的实际页面、备注、媒体和哈希，与最近记录/构建输入对照。用户说手改了，或哈希不符时，当前文件作为编辑基准；旧计划是核对依据，不能据其回滚手改。识别影响范围，保存检查点后局部修改。

默认直接编辑当前 PPT 的相关对象。只有确认构建源已吸收当前手改并能保留其余内容时，才允许重新生成；无法可靠保留时暂停覆盖步骤、说明具体缺口，继续独立核查。不能直接运行过期构建脚本。

候选文件、源身份或相互冲突的用户决定无法区分时才询问。普通样式差异不作为覆盖人工修改的理由。

## 同步与恢复

修改后核对本次受影响的 PPT 页面、备注、引言问题名称、右上标签、`03` 页码内容、`04` 资产映射和 `05` 检查记录；更新 `00` 当前链接/哈希/阶段。新决定取代旧决定的位置明确，当前说明不得继续写“未确认”，历史记录则保留其历史身份。

恢复先读 `00` 和当前阶段文件，再查实际 PPT。工具中断记录最后成功步骤和未完成动作；不要把失败调用、旧输出或未检查的保存结果视为完成。

用户明确另做不同场次时才建 `场次/<场次名>/`，共享 `00/01`，新场次保存自己的 `02–05`、原图和汇报，不搬迁旧成果。
